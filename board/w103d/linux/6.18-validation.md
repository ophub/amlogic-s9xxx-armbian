# Linux 6.18 compatibility validation

Target source: `unifreq/linux-6.18.y` commit
`6943daf37ba41998e600f2249a9b84030290b37c`, Linux 6.18.49.
Configuration baseline: ophub/kernel `kernel-config/release/stable/config-6.18`,
with `w103d-6.18.config` merged and `olddefconfig` run by the build helper.
Baseline config SHA-256:
`36a2cc35ec97b62079c22a4f365620c4a14337f8f6ff382d4b4e01b72d596b1b`.
Cross compiler: Ubuntu GCC 13.3.0 (`aarch64-linux-gnu-`); pahole 1.25.

## Reproduce

From this repository, on Linux with the ARM64 GCC cross toolchain,
Python 3, GCC and the kernel's build dependencies installed:

```sh
python3 board/w103d/validation/verify_patch_series.py "$KERNEL_SRC" --series 6.18
for patch in "$PWD"/compile-kernel/tools/patch/linux-6.18.y/*.patch; do
    git -C "$KERNEL_SRC" apply "$patch"
done
bash board/w103d/validation/build-kernel.sh \
    "$KERNEL_SRC" "$KERNEL_OUT" "$OPHUB_CONFIG_6_18" 16
python3 compile-kernel/tools/mt76/tests/test_rx_enhance.py
python3 compile-kernel/tools/mt76/tests/test_combo.py
```

Use a clean checkout of the pinned revision for the first command.
Use LF line endings for patch files when applying them directly on Linux;
the validation helper normalizes Windows CRLF checkouts in its temporary
directory. The build helper does not deploy or package its outputs.

## Port scope

The six 6.18 patches preserve the same W103D DTS and isolated Wi-Fi/combo
implementation as 6.12. Board-registration and Bluetooth-remove contexts
are rebased to the new source. The Bluetooth provider retains upstream
6.18's close-work synchronization, MT7668-specific changes, HCI quirk APIs
and runtime-PM behavior. HCI readiness is still published after post-init.

The existing 6.12 patch series and driver review copies are unchanged.
The replacement upstream submission includes both validated kernel series.

The W103D model entry accepts `stable/6.12.y_6.18.y` while keeping
`BUILD=no`. Explicit 6.18 image work can select the new series; automatic
image building remains excluded from automatic multi-board batches;
explicit W103D builds check the final assembled firmware and kernel set.

## Validation status

Clean patch application on the complete pinned source, source-copy
equivalence, native RX enhance/combo tests and the 3552-case MMC IRQ harness
have passed. The new verifier also passed the unchanged 6.12 series.

The DTB compiled successfully. Decoded properties confirm the model and
compatible strings, 2 GiB memory, SDIO on `/soc/mmc@ffe05000` at 200 MHz and
4-bit SDR104 with fixed 1.8 V, SD_EMMC_A disabled, and 8-bit/200 MHz eMMC.
The DTB is 79,040 bytes, SHA-256
`575941edacfc2bb4c2c5710ec769efcb9b3e79d48274d2d64c4df8d6b3571294`.

The full ARM64 build completed on 2026-09-05 with `LOCALVERSION=-ophub`:
Image, DTB, MODPOST, BTF and all 2,955 modules passed. Wi-Fi, Bluetooth,
Meson MMC and pinctrl compiled without changing the shared driver code.
Unmodified upstream/vendor code emitted warnings (unused helpers, missing
prototypes and discarded const qualifiers); none occurred in the W103D
driver, MMC, Bluetooth or pinctrl compilation.

The Image is 47,856,128 bytes with a valid ARM64 boot header, SHA-256
`240fe46b01ebb85ca2c1628900d4610e024a765b2e557e96aecbaeb427d6e9e5`.
Both `mt7663s.ko` and `btmtksdio.ko` report
`6.18.49-ophub SMP preempt mod_unload aarch64`; their release fields were
checked for exact equality, not a version-prefix match.
The Wi-Fi alias is `sdio:c*v037Ad7603*`. Its dependencies include
`mt76-connac-lib`, `mt7663-usb-sdio-common`, `mt7615-common`, `mt76-sdio`,
`mt76`, `mac80211`, `cfg80211` and the combo provider `btmtksdio`.

## Hardware validation

On 2026-09-06, the same W103D booted `6.18.49-ophub` from USB storage using
a matched Image, DTB, initramfs and complete module directory. The kernel,
Wi-Fi and Bluetooth live build IDs matched this build. The previous 6.12
boot files and module directory were preserved; no 6.18 module was loaded
into a running 6.12 kernel and no vermagic was changed.

The board used only its onboard MT7663S for management, data and TCP ACKs;
USB network adapters were absent and Ethernet had no carrier. SDIO remained
4-bit SDR104 at 199,999,997 Hz and 1.8 V. CPU governor `schedutil` and Wi-Fi
power saving stayed enabled; temporary IRQ affinity tests restored `0-3`.

Four latency runs (baseline, IRQ sharing the sugov CPU, separate CPU, and
same-CPU repeat) each received all 12 replies, with 2 ms medians and 1–3 ms
ranges overall. Three 100 MiB downlink transfers achieved 413.449, 392.054
and 355.216 Mbps; three 100 MiB uplink transfers achieved 73.850, 70.882
and 77.202 Mbps. Concurrent 512 MiB downlink and 256 MiB uplink transfers
completed at 186.296 and 54.876 Mbps over their respective full durations.
These are receiver byte-count results, not sustained-rate guarantees; the
concurrent transfers finish at different times and their means must not be
added to describe simultaneous steady-state throughput.

Ten complete Wi-Fi/Bluetooth unload-reload cycles, loading only `mt7663s`,
all restored Wi-Fi automatically with identical MAC and full EEPROM/OTP
hashes. Three Bluetooth power on/off cycles passed and restored the initial
power setting. Long-duration stress, cold power cycles, suspend/resume and
eMMC installation remain untested.

A subsequent normal reboot automatically restored onboard Wi-Fi. After
reboot, 100 MiB downlink/uplink tests completed at 447.472/78.638 Mbps;
concurrent 512 MiB downlink and 256 MiB uplink tests completed at
239.914/57.588 Mbps. The two traffic batches transferred 2,336 MiB in total.
Final verification again matched kernel/module live build IDs, boot-file
hashes and EEPROM/OTP contents. All MMC error counters were zero, with no
kernel WARNING, BUG, Oops or atomic-sleep report. The final 20 idle pings
all replied: 2 ms median, 1–3 ms range. The board remains on 6.18.49-ophub;
restoring its saved 6.12 `uEnv.txt` selects the preserved 6.12 boot set.

The overlay now includes the exact factory 2021 N9 and linux-firmware ROM
patch used in these tests. An assembled tree made from the overlay and the
tested kernel/modules/initramfs passed `verify_image.py`. Substituting the
old 2020 N9 or disabling the combo configuration made that check fail, as
required. The compiler workflow also merges the board config automatically.
No full newly generated disk image was booted in this check; the earlier
hardware run used the same verified component bytes installed on USB.
See `../firmware/README.md` for binary provenance and the exact-version N9
licensing question still requiring upstream review.
